# Atmospheric acquisition and materialisation

This is an experimental, explicitly supported file boundary, not a universal atmospheric-provider adapter or a qualified background-atmosphere product. Acquisition, local extraction and numerical materialisation are separate operations. `orsia-data` knows native files and providers; `orsia-radiative` owns the pure hydrostatic/conservation calculations and the existing `Atmosphere`. The study chooses products, editions, source combinations, interpolation assumptions and missing-data policy. Nothing in a numerical calculation downloads or substitutes a missing source. `read_pressure_level_atmosphere` provides a direct offline pressure-level NetCDF → `Atmosphere` path; native hybrid-level coefficients and composition combinations remain explicitly supplied rather than inferred.

## Acquisition

`download_era5(product=..., request=..., retrieve=..., destination=...)` accepts the explicit CDS identifiers `reanalysis-era5-pressure-levels`, `reanalysis-era5-single-levels` and `reanalysis-era5-complete`. `download_cams` distinguishes ADS `cams-global-greenhouse-gas-forecasts` from `cams-global-atmospheric-composition-forecasts`. These are product selections, not pinned editions or guarantees that every requested variable is available. Supply a configured client's synchronous `retrieve(dataset, request, target)` method; Orsia does not install a client, read credentials, accept licences, set its retries or infer the contents of the native request. Choose dates/cycle/lead, fields, area, levels and format explicitly. Archive/edition coverage and request schemas still need qualification against the selected service. See the official [ERA5 documentation](https://confluence.ecmwf.int/spaces/CKB/pages/76414402/ERA5+data+documentation), [CAMS GHG catalogue](https://ads.atmosphere.copernicus.eu/datasets/cams-global-greenhouse-gas-forecasts?tab=overview) and [CAMS composition catalogue](https://ads.atmosphere.copernicus.eu/datasets/cams-global-atmospheric-composition-forecasts?tab=overview).

CDS/ADS retrieval writes in an exclusively owned private temporary directory, checks for a nonempty regular file and a post-transfer byte limit, optionally verifies SHA-256, then publishes by atomic no-clobber hard link. Existing destinations are preserved, including a racing writer. Every failure cleans up the private directory; parents may remain. The byte limit is not a streaming bound on the SDK transfer. SDK/network exceptions propagate; the caller owns credentials, concurrency, cancellation and deadlines. Native requests are deep-copied before submission and must not be mutated concurrently by the caller.

`download_gfs(cycle=..., lead_hours=..., variables=..., levels=..., area=..., destination=...)` builds a NOMADS 0.25-degree GRIB2 subset request. Use acquisition codes such as `TMP`, `SPFH`, `UGRD`, `VGRD`, and native level selectors such as `1000 mb` or `surface`; no list is selected for the study. `area=(west,east,south,north)` uses a non-wrapping rectangle with longitude in [0,360]. Cycle is an exact UTC 00/06/12/18 hour, distinct from the validity returned by `gfs_valid_time(cycle, lead_hours)`. Leads are hourly through 120 h and three-hourly through 384 h. This request resolver is not a guarantee of current NOMADS retention or field availability; see the [NOAA product inventory](https://www.nco.ncep.noaa.gov/pmb/products/gfs/). Transport uses `download_file`'s bounded streaming/no-clobber semantics; an HTTP error page must still fail local GRIB decoding. No historical archive or ERA5 fallback is attempted.

Retain native bytes for offline replay. `file_sha256(path)` gives a streaming byte fingerprint, not authenticity or coverage. Keep product/version, file identity, native request, cycle/lead/validity, actual spatial support, units, conversions and assumptions in caller-owned acquisition records, excluding credentials. Numerical atmospheric contracts deliberately contain no provider identity; no new generic manifest or provenance framework is introduced.

## Local extraction

`read_rfm_atmosphere(path)` decodes native RFM point profiles into independent writable float64 arrays for altitude [m], pressure [Pa], temperature [K] and gas mole fractions relative to total air. `services.mipas.download_mipas_profile` separately acquires one of five MIPAS 2001 reference atmospheres. See the [reference-atmosphere contract and example](mipas-reference-atmospheres.md) for the supported molecular vocabulary, grammar, physical checks, concentration preservation and authentic-file replay evidence.

`read_netcdf_profiles(path, variables=..., coordinates=..., vertical_units=..., valid_time=..., latitude_deg=..., longitude_deg=..., backend=...)` returns `(native_vertical_coordinate, native_variable_profiles)`. `variables` maps native names to exact required native unit strings; `coordinates` names the one-dimensional `(time, vertical, latitude, longitude)` coordinate variables. Fields must have exactly those dimensions, in any order. It does not infer pressure from a model-level number, infer species from a variable name, convert units silently or choose an ensemble/expver/cycle/lead axis. Such extra dimensions must be selected explicitly upstream. Surface/context fields use `read_netcdf_surface_fields` with `(time, latitude, longitude)` coordinates and return scalars, for example surface pressure, 10 m wind, boundary-layer height, surface temperature or cloud screening. These values are not automatically plume winds, surface optical parameters or cloud optics.

Spatial/time extraction is linear interpolation within declared coordinate coverage; ascending and descending coordinates work. Singleton axes require exact selection. Missing/nonfinite bracketing values fail; exact coordinates do not consume an adjacent missing cell. `vertical_interval=(min,max)` optionally selects inclusive native vertical coordinates before validating fields, so missing below-terrain levels can be excluded explicitly. Packed fields apply fill/missing/validity checks before scale and offset. `_Unsigned` reinterpretation is rejected rather than guessed. Time supports seconds/minutes/hours/days since an ISO epoch and standard/gregorian calendars; other calendars fail. This is not a general CF decoder. Periodic longitude is enabled only by an explicit `periodic_longitude=True`; callers must establish full global coverage before allowing interpolation across the seam. Regional subsets default to no wrapping or extrapolation. Returned buffers are fresh writable float64 arrays detached from the file; source files must not change concurrently.

The default `backend="classic"` selects xarray's SciPy engine for NetCDF CDF-1/2. `backend="hdf5"` selects its optional `h5netcdf`/`h5py` engine for NetCDF4/HDF5 without selecting groups or extra dimensions implicitly. Engine choice is explicit: neither `netCDF4` nor automatic engine detection is used. xarray is a declared base dependency so classic files remain readable without an extra; install `orsia-data[atmosphere]` for HDF5 and GRIB. Orsia uses named dimensions and bounded `isel` selections before CF mask/scale decoding, with no Dask dependency or full provider-cube load. Orsia retains packed `valid_range`/`valid_min`/`valid_max` checks because xarray's CF decoding does not enforce those bounds. xarray datasets stay internal; public readers still return NumPy arrays/scalars. Importing Orsia never imports the optional backends or a provider SDK. Backend calls are synchronous; caller-owned serialization remains required where the native library does not support concurrent access.

`read_gfs_profiles` uses xarray's optional cfgrib engine over ecCodes and requires explicit native short names/units, decreasing `pressure_levels_pa`, cycle, lead and location. It supports deterministic instantaneous GRIB2 `regular_ll` fields on `isobaricInhPa` levels, converts requested hPa identity to Pa and requires every requested field/level exactly once for the requested cycle and validity. Missing/duplicate/ensemble/accumulated/malformed samples fail. An ecCodes metadata preflight remains necessary because cfgrib can coalesce duplicate messages; format decoding and grid construction are delegated to cfgrib. Exact filters select requested levels, variable, cycle, validity and native grid; levels with different grids are decoded separately. Native handles and xarray datasets are released on success and failure. One horizontal field is decoded at a time, not a multi-level provider cube. Disk indexes and cfgrib's global geometry cache are disabled. Targeted scan-order corrections preserve consecutive-j, westward and wrapped-longitude storage, which cfgrib 0.9.x otherwise pairs incorrectly with its dimensions/coordinates; generated scan-order tests must be rerun when upgrading cfgrib. The reader does not decode hybrid/surface GRIB messages, infer interfaces, expose all GFS context fields or silently choose the nearest forecast. The Python extra requires a separately installed native ecCodes library; this repository provisions ecCodes 2.48.0 through Devbox and supplies `ECCODES_DIR` in the optional test recipes.

## Numerical materialisation

`orsia_data.read_pressure_level_atmosphere` combines offline NetCDF extraction with the pure numerical functions below. Declare native temperature/q variable names, q units, Pa/hPa coordinate units, location/time, surface pressure, target interfaces, gravity and bottom height. It excludes pressure knots below the explicitly supplied terrain surface pressure and requires the remaining knots to bracket every target interface; it never manufactures a surface knot. K and dimensionless SI specific humidity are required, not RH/g/kg/dry-air mixing ratios. Gas columns must already be materialised on the selected target layers. For native hybrid levels, the caller reconstructs interface pressures and supplies them with layer fields to `hydrostatic_atmosphere`.

The public numerical functions are exported by `orsia_radiative`:

| Function | Explicit convention |
| --- | --- |
| `pressure_level_layer_means(pressure_pa, values, pressure_boundaries_pa)` | Caller-selected reconstruction linear in pressure, integrated into pressure-mass layer means; fully bracketed support, never interface inference or extrapolation. |
| `specific_humidity(ratio)` | kg water/kg dry air → kg water/kg total moist air. |
| `gas_columns_from_fraction(..., convention=..., gravity_m_s2=..., molar_mass_kg_mol=...)` | Explicit dry/total-air mole or mass fractions → molecules/m2; a species molar mass [kg/mol] is required for mass fractions. |
| `remap_layer_columns(source_interfaces, columns, target_interfaces)` | Extensive layer quantities conserved by pressure overlap, assuming constant amount per Pa within each source layer. |
| `hydrostatic_atmosphere(...)` | Existing bottom-to-top `Atmosphere`, pressure Pa, T K, columns molecules/m2, independent writable copies. |
| `geometric_height(..., reference_gravity_m_s2=..., earth_radius_m=...)` | Explicit spherical conversion z=R H/(R-H), H=geopotential/g0; not a geoid/datum correction. |

Hydrostatic layer mass is Δp/g. Water and dry molecule columns are q Δp/g/Mwater NA and (1-q) Δp/g/Mdry NA, with fixed molar masses 0.01801528 and 0.0289647 kg/mol and NA=6.02214076e23 mol−1. Gravity is explicit and constant. Trace gases are additions within the dry-air pool, not changes to the fixed mean molar mass. `hydrostatic_atmosphere` inserts H2O from q, remaps gas/dry/water columns by pressure overlap, preserves total=dry+water and uses pressure-mass weighted temperatures. Target midlayer pressures are arithmetic interface means. Approximate geometric heights use a hypsometric calculation with a pressure-mass weighted R_specific T in each target layer, anchored by `bottom_height_m` at the target bottom. This is an explicit approximation, not a native altitude reconstruction or a claim of height-grid invariance under remapping. Zero model-top pressure may be reconstructed, but finite hydrostatic height requires a positive target top.

Gas composition on another product grid must be converted to columns using that product's own air/humidity convention, then remapped explicitly onto the meteorological source grid. Equal pressure support preserves the integrated gas amount; a narrower target deliberately discards the outside column. Product surface pressure, terrain, coverage and time differences must be resolved by the caller before combination. No gas climatology or reference profile fills gaps. Filter pressure knots below terrain before reconstruction; if the remaining knots do not bracket the surface, obtain valid surface/model-level information or materialise an explicitly partial column instead of extrapolating. Hydrostatic construction alone cannot determine which supplied native values were extrapolated below terrain by a provider.

For a local/synthetic layer column, with no network or files:

```python
import numpy as np
from orsia_radiative import gas_columns_from_fraction, hydrostatic_atmosphere

p = np.array([100000.0, 60000.0, 20000.0])  # source interfaces, bottom to top [Pa]
t = np.array([280.0, 240.0])               # layer means [K]
q = np.array([0.01, 0.02])                 # kg water/kg moist air
ch4 = gas_columns_from_fraction(
    p, q, np.array([1.8e-6, 1.8e-6]), convention="dry_air_mole", gravity_m_s2=9.80665,
)
atmosphere = hydrostatic_atmosphere(
    p, t, q, target_pressure_boundaries_pa=np.array([100000.0, 80000.0, 20000.0]),
    gravity_m_s2=9.80665, bottom_height_m=0.0,
    gas_columns_molecules_m2={"CH4": ch4}, air_broadener="dry_air",
)
```

This supplies the existing input to spectroscopy and radiative calculations, not a prior covariance or a resolved local plume. Wind and screening inputs stay separate from radiative atmosphere materialisation. CAMS aerosol concentration profiles may be read and conservatively remapped as mass columns, but they do not determine extinction, single-scattering albedo or phase function without a caller-selected optical model. No CAMS-to-aerosol-optics converter, spectral AOD inversion, cloud or ice optical model is implemented.

## Verification and limits

Run `devbox run -- just test-atmosphere`, `devbox run -- just runtime-atmosphere test-atmosphere-backends`, `devbox run -- just clean-install-atmosphere`, and the repository-wide `devbox run -- just check`. The optional clean-install recipe replays generated native files against installed wheels outside workspace import resolution; it explicitly excludes the incompatible PyPI `eccodeslib` bundle while retaining other transitive dependencies and using Devbox's native ecCodes. Offline tests use analytic columns, synthetic classic-NetCDF fields, mocked clients/transports/ecCodes/xarray boundaries, and generated native GRIB2/HDF5 files. They cover units/packing, reordered axes, spatial/time interpolation and longitude seam policy, validity/cycle identity, missing fields/support, resource release, no-clobber/failure cleanup, dry/moist/mass fraction conventions and conservation on split/merged/partial grids. Import/runtime checks observe the GIL without forcing it off; native generated-file tests also check it after reading. Disabled GIL and successful generated-file replay do not establish concurrent native-library safety or provider/scientific qualification.

During backend selection, `netCDF4` 1.7.4 enabled the GIL and was replaced by `h5netcdf`/`h5py`. The ecCodes binary PyPI bundle lacked a wheel for this free-threaded platform, so the native dependency is provisioned by Devbox rather than that Python bundle. No live ERA5/GFS/CAMS request, authentic provider file, archive-edition/field qualification, external atmospheric comparison, optical conversion or retrieval-performance evaluation was performed. Public catalogue/endpoint references support request identity only, not tested live behavior. NOAA's inventory and the NOMADS directory/selector pages were read during implementation; no GRIB subset was requested. Provider fallback, campaign policy, automatic caching, persisted acquisition records and study integration remain outside this library increment.
