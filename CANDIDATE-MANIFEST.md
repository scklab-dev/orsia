# Source manifest

## Source and selection

This source tree was assembled from tracked blobs at Orsia commit `bc1cd72da7c1be77ed76b084687a8c712f4ad9f7`. Its Git history starts with one independent root commit. The original Orsia Git history remains in its original checkout.

- The tree includes six complete `libs/orsia-*/` trees: distribution metadata, library source, synthetic fixtures, library tests, guides and locally produced Draw.io source and SVG/PNG exports. The native C++ source is part of the radiative distribution.
- The root includes `.gitignore`, `.python-version`, `devbox.json`, `devbox.lock`, `pyproject.toml`, `uv.lock`, the development `scripts/check_*` files and 16 original root tests selected from tracked HEAD. The notebook addition includes `.env.example`, two canonical notebooks, their seven Python support modules, the derived Toulouse scenario JSON, three preparation/replay scripts, five focused notebook tests, one portability test and the five-band enrichment guide. Notebook JSON, Python companions, scripts, original tests and scenario data were copied from the original checkout; the clone-specific instructions, credential loader and replay contract have been adapted here.
- The `docs/` directory includes the seven original library composition/data-service guides and `five-band-enrichment.md`.
- The `justfile` targets the included source, tests and notebook workflows. The root README links the notebook guide. The root and each distribution include the Apache License, Version 2.0 text; the root and six package metadata files declare `Apache-2.0`. Each built wheel and source distribution carries its package license file.
- The original checkout retains its `.git` and `.agents/` trees, `AGENTS.md`, historical `reports/` and its own outputs. Acquired atmospheric inputs, private credentials, caches, executed archive NPZ files, kernelspecs and other ignored products remain local to the user's environment. The published notebooks retain their embedded historical displays; current-source results require a fresh explicit execution. The scenario JSON contains derived geometry and identifies Space-Track GP_HISTORY and Skyfield as source and processing method; raw orbital elements remain in the original checkout.
