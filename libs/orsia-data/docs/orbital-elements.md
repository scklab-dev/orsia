# SGP4 mean elements and acquisition

## Ownership and entry points

Data owns authenticated Space-Track acquisition, local GP OMM JSON/TLE interpretation and native-byte provenance. Geometry owns the immutable scalar `SGP4MeanElements` contract, propagation and frame transformations. Data declares a dependency on Geometry; Geometry remains independent of Data. Install `orsia-data[orbital]` for parsing and acquisition validation. This extra supplies SatKit 0.24.1 and Geometry's matching orbital extra. The private parser is loaded only when decoding or downloading elements. Local reading never authenticates, downloads or loads propagation auxiliaries.

- `parse_orbital_elements(payload, format=...)` parses acquired bytes into `list[SGP4MeanElements]`.
- `read_orbital_elements(path, format=..., max_bytes=...)` reads a bounded local UTF-8 file with the same return contract.
- `select_orbital_elements(elements, object_ids=..., element_epoch_interval_utc=...)` selects each requested object's latest set within the inclusive epoch interval, without I/O or a backend import.
- `orsia_data.services.space_track.SpaceTrackClient` owns an explicit synchronous cookie session and publishes original bytes with separate provenance.

Import the three orbital-element functions from `orsia_data` or `orsia_data.orbits`.

## Scalar records and selection

Import `SGP4MeanElements` from `orsia_geometry` or `orsia_geometry.orbits`. The frozen, slotted record contains a numeric `norad_id`, timezone-aware UTC `epoch`, dimensionless `eccentricity`, `inclination_rad`, `raan_rad`, `argument_of_perigee_rad`, `mean_anomaly_rad`, `mean_motion_rad_s`, signed `bstar_per_earth_radius`, full `mean_motion_dot_rad_s2` and `mean_motion_ddot_rad_s3`, and optional `object_name`. All numerical values are finite. Mean motion is positive, eccentricity lies in `[0,1)`, inclination in `[0,pi]` and other angles in `[0,2*pi)`. The record represents Earth-centred TEME/UTC mean elements for classic SGP4. Epoch precision is one microsecond. Acquisition details, source extensions and non-propagating catalogue metadata remain in the native payload and receipt.

Readers convert native angles from degrees to radians and mean motion from revolutions per day with `2*pi/86400`. For the supported GP OMM JSON and TLE conventions, the source first derivative is `n-dot/2` in rev/day² and the source second derivative is `n-ddot/6` in rev/day³. The full scalar derivatives use factors `2 * 2*pi / 86400²` and `6 * 2*pi / 86400³`. Geometry reverses these factors when constructing its private native SGP4 record. Classic SGP4 retains these derivatives without using them in its state calculation. The pinned parser's field definitions and conversion are in SatKit commit `441675131bf9b14a9634d069f7f2599b69c7252c`, `python/src/pytle.rs` and `src/omm/mod.rs`. These GP derivative conventions limit this reader's OMM scope.

`format="omm"` accepts GP JSON objects or arrays. Required orbital values are `EPOCH`, `NORAD_CAT_ID`, `MEAN_MOTION`, `ECCENTRICITY`, `INCLINATION`, `RA_OF_ASC_NODE`, `ARG_OF_PERICENTER`, `MEAN_ANOMALY`, `BSTAR`, `MEAN_MOTION_DOT` and `MEAN_MOTION_DDOT`. Numeric JSON values and numeric strings are accepted. The catalogue identity must represent an exact positive integer at most `2147483647`, matching the native signed-32-bit domain. Epochs must be UTC strings; an omitted timezone suffix means UTC under the GP convention. Explicit nonzero offsets fail. The accepted GP defaults are `TIME_SYSTEM=UTC`, `REF_FRAME=TEME`, `CENTER_NAME=EARTH` and `MEAN_ELEMENT_THEORY=SGP4`; supplied conflicting values fail. XML/KVN OMM and SGP4-XP are unsupported.

`format="tle"` accepts numeric-catalogue two-line sets with an optional name line. Data enforces 69 ASCII characters and matching numeric object IDs; the private SatKit parser validates checksums and interprets orbital values. The scalar record validates physical domains. TLE epoch years 57 through 99 mean 1957 through 1999; years 00 through 56 mean 2000 through 2056. Alpha-5 TLE identifiers remain outside the reader's supported scope, even when the backend accepts them. Original bytes remain the source for exact replay and provenance. Malformed or unsupported payloads raise `ValueError`; a required SatKit installation that cannot load raises `ImportError`.

`select_orbital_elements` takes parsed records, explicit nonempty distinct positive `object_ids`, and an inclusive ordered timezone-aware UTC `element_epoch_interval_utc`. For each requested object, the latest epoch within the bounds wins; equal epochs retain input order. The returned fresh list follows requested object order and shares immutable records with the input. Missing requested objects or accepted sets raise `ValueError`. Applications choose epoch bounds from their prediction-age policy and retain their evaluation interval separately. The selector performs no UTC-duration arithmetic or evaluation-start check. Element availability, acquisition time and file coverage establish no prediction accuracy.

Read with `elements = read_orbital_elements(path, format="omm")`, select with `selected = select_orbital_elements(elements, object_ids=(25544,), element_epoch_interval_utc=(earliest, latest))`, then pass `selected[0]` directly to Geometry's `SGP4Propagator`. The TLE route returns the same scalar type. Callers supply the evaluator's UTC `epoch` and accepted `validity_s` independently.

### Migration

The current module is `orsia_data.orbits`. The previous Data module and SGP4-specific function names are removed without compatibility aliases. Use `read_orbital_elements` for local files, `parse_orbital_elements` for acquired bytes and `select_orbital_elements` for latest-per-object selection within explicit epoch bounds. Signatures and behavior are unchanged by this naming refactor.

Geometry's `SGP4MeanElements` is defined in `orsia_geometry.orbits` alongside the propagators. The package-root export remains available. Replace direct imports from the removed `orsia_geometry.sgp4_elements` module with imports from `orsia_geometry.orbits`; the old module has no compatibility alias. The record's constructor, validation, units and immutable scalar fields are unchanged. Importing the record or Data's readers and selecting existing records leaves SatKit unloaded; decoding payloads loads the required SatKit parser.

The older `orbital_elements` dictionary API and composite preparation receipt remain removed. Callers of that API must consume the scalar records returned by the current readers. Replace `prepare_orbital_elements` with explicit reading followed by `select_orbital_elements`; preserve acquisition provenance through original bytes and the existing Space-Track receipt. Pass scalar records to `SGP4Propagator` instead of dictionaries or TLE-line tuples. The public functions return immutable `SGP4MeanElements` records.

## Space-Track session

Construct `SpaceTrackClient(credentials, ...)` with a borrowed zero-argument supplier returning `(identity,password)`. Construction does no network access or credential discovery. `download(object_ids, destination, format="omm", history_utc=None)` logs in on demand, combines object IDs into one query and retrieves newest `gp` sets. An explicit ordered whole-second UTC `history_utc=(start,end)` selects `gp_history` instead. Use the newest GP route for current elements. The session has no arbitrary URL or query-string interface.

The default transport sends requests only to `https://www.space-track.org` with proxies disabled. Redirects fail before credentials, POST bodies or cookies can follow a different location. Cookies remain in memory and are cleared on close. A supplied test/transport opener is borrowed and must enforce the same security policy. Context-manager exit invalidates the client and drops credential/opener references. Remote revocation and secure memory erasure are outside that operation. Use one client serially; callers coordinate all other sessions that share the account.

The [Space-Track documentation](https://www.space-track.org/documentation), API Use Guidelines checked 2026-11-02, requires fewer than 30 requests per minute and 300 per hour, GP retrieval at most hourly and local retention of downloaded histories. The client counts authentication, retries and queries against conservative local limits of 29/minute and 299/hour. All GP queries and retries share at least 3600 s spacing within a client. Successfully retrieved exact history selections cannot be retrieved again within that session. These controls cannot account for another client, process or account user. Persist/reuse histories and coordinate account-wide retrieval policy. Scheduled hourly GP jobs should avoid the top and bottom of the hour under the service guidance.

Login accepts an empty body, an empty JSON object or an empty JSON string. Explicit failures, HTML and other JSON values raise a redacted authentication error before any element query. `attempts` defaults to one and can be at most three. Authentication and nonretryable request failures stop immediately. Transport, HTTP 429 and 5xx failures can retry, subject to per-client pacing, exponential backoff, `Retry-After` and a cumulative waiting budget. `max_wait_s` defaults to 30 s per request. A GP retry normally exceeds that budget because hourly class spacing still applies; the client fails explicitly instead of waiting implicitly for an hour. Timeouts bound each network operation, independently of cumulative waits. `max_bytes` bounds every response. Service/authentication errors omit server response bodies, supplier exceptions and credentials from the delivered error text.

Before authentication or any request, `download` loads the required SatKit parser. An absent or unusable orbital extra raises `ImportError` before credentials or network access. The payload must decode under the selected local schema and contain exactly the requested object identities. Empty, invalid, unrequested or incomplete selections fail before publication. A successful download publishes native bytes without overwriting a destination, then creates `destination.provenance.json` exclusively. The receipt records provider, canonical credential-free query, acquisition UTC, format, payload SHA-256, selected object IDs and normalized timezone-aware UTC element epochs. A receipt-write failure can leave the complete payload for explicit local reuse. Existing payloads/receipts fail before login; refresh requires an explicit new destination. Credentials, cookies and login responses are excluded from persisted outputs.

On 2026-11-02, a bounded authorized live check reproduced rejection of an HTTP 200 login response containing an empty JSON string; the session cookie was accepted by the existing cookie policy. After the response-validation repair, one login and one current-GP OMM request for one object succeeded with the default transport. The existing reader parsed the retained payload, and its hash and element epoch matched the provenance receipt. This observation establishes that account's tested authentication/download path; history queries, other accounts, sustained operation and propagation accuracy remain outside this live check. Mocked requests separately check the session/software contract.

## Propagation resources

SatKit owns its normal public auxiliary search, acquisition and process-global EOP/JPL caches. The redundant Data auxiliary-preparation wrapper and its script/recipe are removed. General Data file-acquisition functions remain available. The fixed local native tests use the existing files under `outputs/geometry-auxiliaries` with offline mode; tests never acquire missing files. Applications can use ordinary backend resource management independently of element parsing. See [Geometry's resource and numerical evidence contract](../../orsia-geometry/docs/geometry.md#resources-provider-boundary-and-execution).
